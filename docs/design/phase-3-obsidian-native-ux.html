Phase 3 accepted / Obsidian-native UX layer

kanban-task-engine의 주 UX를 CLI에서 Obsidian으로 옮긴다

사람은 Obsidian에서 카드와 노트를 다루고, ID 채번, frontmatter 보정, board projection, reconcile, 상태 전이는 repo-local Obsidian companion plugin과 core engine이 처리한다. CLI는 운영 보조, CI, 복구용 surface로 남긴다.

Decision Shape Status: Accepted
Accepted: 2026-05-14
Primary UX: Obsidian
New package: obsidian plugin
Engine truth: Markdown issues
Adapter: Obsidian Vault API
CLI role: fallback/debug

1. 목표 UX

사람이 매일 쓰는 흐름에서 터미널을 제거한다.

2. Component Boundary

Plugin은 얇게, core use-case는 재사용 가능하게.

Human Layer

Obsidian 안에서 조작

카드 생성, 현재 note normalize, board sync, move preview, apply를 Command Palette와 ribbon에서 실행한다.

Plugin Layer

Vault-aware adapter

Obsidian Vault API로 파일을 읽고 쓰며, dry-run diff와 apply confirmation을 UI로 노출한다.

Core Layer

Deterministic use-cases

ID 채번, issue 생성, normalize, move, reconcile, board render는 CLI와 plugin이 같은 함수를 쓴다.

Data Layer

Markdown source of truth

실제 상태는 issue frontmatter에 남고, board/index는 생성 projection으로 유지한다.

별도 플러그인인가?

Accepted: 외부 앱이나 별도 SaaS가 아니라 이 repo 안의 Obsidian companion plugin을 만든다. 기존 Kanban/Dataview plugin은 board 표시와 조회를 맡고, kanban-task-engine plugin은 ID 채번, issue 생성, rough note 승격, board move preview/apply 같은 engine-specific UX를 맡는다.

3. Command Surface

CLI 명령을 사람이 쓰는 UX로 그대로 노출하지 않고, Obsidian 작업 단위로 재구성한다.

Obsidian Command 사용자 경험 Engine Mapping 완료 조건
Kanban: New Task title만 입력해도 ID와 기본 frontmatter가 채워진 issue 생성 new use-case issue 생성 후 board에 카드가 보임
Kanban: Normalize Current Note rough note를 canonical issue로 승격 normalize --write use-case frontmatter/schema validation 통과
Kanban: Sync Current Board 현재 space의 board/index 재생성 board --write --space use-case Kanban plugin이 board view로 렌더
Kanban: Preview Board Moves Obsidian에서 이동한 카드의 status diff를 modal로 확인 reconcile-board --dry-run use-case 예상 move만 표시하고 apply는 아직 안 함
Kanban: Apply Board Moves diff 확인 후 issue frontmatter에 반영 reconcile-board --apply use-case issue status와 regenerated board metadata가 일치
Kanban: Move Current Issue 현재 note에서 안전한 status transition 수행 move use-case invalid transition은 UI에서 차단

4. Raw Card 처리

사람이 board에 막 만든 카드를 canonical issue로 승격하는 흐름.

5. Delivery Plan

MVP는 작게, 하지만 “Obsidian만 써도 된다”는 기준을 반드시 통과한다.

3A. Plugin Scaffold manifest, settings, dev reload, vault detection, command registration.
3B. Core Extraction CLI handler에서 use-case 함수를 분리해 plugin이 직접 호출.
3C. New + Sync New Task modal, board/index regenerate, Obsidian render smoke.
3D. Preview + Apply board move diff modal, apply, status/writeback conflict guard.
3E. Raw Promotion metadata 없는 card/note를 issue로 승격하는 guided flow.

6. Risk Gates

Phase 3에서 반드시 막아야 하는 실패 모드.

Blocker

board가 source of truth가 되는 문제

board는 projection이다. apply 전 이동은 proposal이고, 최종 상태는 issue frontmatter에만 확정된다.

Blocker

Obsidian cache와 외부 write 충돌

plugin write는 Vault API/process 기반으로 처리하고, 외부 CLI write와 충돌하면 preview에서 멈춘다.

Blocker

사람이 metadata를 직접 편집하는 문제

metadata comment는 generated 영역으로 유지하고, 수정 감지 시 apply를 막고 regenerate를 제안한다.

Acceptance

터미널 없이 task 생성

Obsidian에서 제목만 입력하고 만들기를 누르면 새 카드가 board에 바로 보여야 한다.

Acceptance

GUI move reconcile

Obsidian에서 이동한 카드가 preview diff와 apply를 거쳐 issue status로 반영되어야 한다.

Acceptance

regenerate 후 일관성

board lane, metadata status, issue frontmatter가 같은 status를 보여야 한다.

Evidence

copy-installed smoke

obsidian-plugin:smoke-setup -- --no-gui가 disposable vault, plugin copy install, registry seed, vault-scoped Obsidian CLI next commands를 생성한다.

Evidence

Desktop GUI runtime

Obsidian 1.12.7에서 copy-installed plugin reload, command list, New Task, raw card promotion, screenshot, dev:errors gate를 통과했다.
